## A1 (P0) — `detect_negated_state` archives facts about OTHER people

**Files:** `src/pmb/reasoning/attributes.py:226-300`, consumed by
`src/pmb/core/engine/write.py:437` (write-time, default ON via
`keyed.archive_obsolete_negations`, config.py:406) and `write.py:515` (repair pass).

**Bug:** `_SUBJECT_RE` (a user cue: I/my/user/я/…) and `_NEGATED_STATE_PATTERNS`
(negation + attribute verb) are tested **independently anywhere in the content**:

```python
# current code — attributes.py:293-299
if not _SUBJECT_RE.search(content):      # "I" matches anywhere…
    return None
for pat, attr in _NEGATED_STATE_PATTERNS:
    if pat.search(content):              # …"no longer lives" matches anywhere
        return attr
```

So `"I learned that Alice no longer lives in Paris"` → subject cue "I" ✓,
negation "no longer lives" ✓ → returns `"city"`. When the user later records
their own city, **Alice's fact is archived automatically**. Same false positive
for `"My sister doesn't work at Google anymore"` → `"employer"`.

**Fix — make subject and negation adjacent inside one clause.** Replace the
decoupled check with composed patterns where the subject sits **directly before**
the negation (at most one adverb between), and sentence-scope the "is unknown"
patterns:

```python
# attributes.py — REPLACE _SUBJECT_RE / _NEG / _NEGATED_STATE_PATTERNS with:

# Subject cue that must sit IMMEDIATELY before the negated verb (one optional
# adverb allowed): "I no longer live", "the user does not currently live",
# "я больше не живу". This is what kills "I learned that Alice no longer lives".
_SUBJ_ADJ = (
    r"(?:i|i'?m|i've|the\s+user|user|я|пользователь\w*)"
    r"(?:\s+(?:still|also|really|currently|всё\s+ещё|уже|сейчас))?"
)
_NEG = (
    r"(?:does\s+not|doesn'?t|do\s+not|don'?t|did\s+not|didn'?t|"
    r"no\s+longer|not\s+currently|больше\s+не|уже\s+не|не)"
)
_UNK = r"(?:unknown|not\s+known|unclear|неизвест\w*)"

# Possessive user cue for the "X is unknown" form — must be in the SAME sentence.
_POSS = r"(?:my|the\s+user'?s|user'?s|мо[йяё]|пользовател\w*)"

_NEGATED_STATE_PATTERNS: list[tuple[re.Pattern, str]] = [
    # "I/user no longer live(s) in …" — subject adjacent to negation
    (re.compile(
        _SUBJ_ADJ + r"\s+" + _NEG +
        r"\s+(?:currently\s+)?(?:live|lives|living|reside|resides|жив\w*)\b",
        re.IGNORECASE), "city"),
    (re.compile(
        _SUBJ_ADJ + r"\s+" + _NEG +
        r"\s+(?:currently\s+)?(?:work|works|working|работа\w*)\s+(?:at|for|в|на)\b",
        re.IGNORECASE), "employer"),
    # "(my / the user's) current city … is unknown" — possessive in same sentence
    (re.compile(
        _POSS + r"[^.;!?]*\b(?:current\s+)?(?:city|location|residence|town|город)"
        r"[^.;!?]*\b" + _UNK + r"\b", re.IGNORECASE), "city"),
    (re.compile(
        _POSS + r"[^.;!?]*\b(?:current\s+)?(?:employer|company|workplace|работодател\w*)"
        r"[^.;!?]*\b" + _UNK + r"\b", re.IGNORECASE), "employer"),
    (re.compile(
        _POSS + r"[^.;!?]*\b(?:current\s+)?(?:country|страна)"
        r"[^.;!?]*\b" + _UNK + r"\b", re.IGNORECASE), "country"),
    # bare "current city is unknown" (no possessive) — ONLY when the sentence
    # also contains a user-subject negation, i.e. the Warsaw corpus case:
    # "the user does not currently live in Warsaw; current city is unknown."
    # Handle by sentence-splitting in detect_negated_state (below), not regex.
]

def detect_negated_state(content: str) -> Optional[str]:
    if not content or len(content) > 400:
        return None
    # evaluate per SENTENCE so a user-cue in one sentence can't license a
    # third-party negation in another
    for sentence in re.split(r"[.!?\n]+", content):
        for pat, attr in _NEGATED_STATE_PATTERNS:
            if pat.search(sentence):
                return attr
        # the Warsaw two-clause form: user-negation clause + "current X is
        # unknown" clause separated by ';' — treat ';' parts of a sentence
        # that ALREADY matched a subject-adjacent negation as covered above;
        # additionally allow "current <attr> is unknown" when the same
        # sentence (incl. ';' parts) contains a subject-adjacent negation.
        if re.search(_SUBJ_ADJ + r"\s+" + _NEG, sentence, re.IGNORECASE):
            m = re.search(
                r"\b(?:current\s+)?(?:city|location|residence|город)\b"
                r"[^.;!?]*\b" + _UNK, sentence, re.IGNORECASE)
            if m:
                return "city"
    return None
```

Keep the function signature; delete the now-unused standalone `_SUBJECT_RE` use
(check other importers first: `rg -n "_SUBJECT_RE" src/`). A2 below wants a
*public* first-person cue helper — add `has_user_subject_cue(content) -> bool`
wrapping the old broad regex for that purpose (broad matching is correct THERE,
it's a prefilter, not an archiver).

**Tests** (extend `tests/test_negation_tombstones.py`):
- `"I learned that Alice no longer lives in Paris"` → `None`; recording
  `user::city` afterwards archives **nothing**.
- `"Alice no longer lives in Paris"` → `None`.
- `"My sister doesn't work at Google anymore"` → `None`.
- `"I no longer live in Paris"` → `"city"`.
- `"The user does not currently live in Warsaw; current city is unknown."`
  → `"city"` (the original corpus case keeps working).
- `"я больше не живу в Варшаве"` → `"city"`; `"Алиса больше не живёт в Париже"` → `None`.
- All existing tombstone tests stay green.

## A3 (P0) — global budget for ALL offline LLM passes

**Problem:** "bounded" today means per-call timeout only.
`suggest_keyed_from_llm` does up to 40 sequential calls × 15 s = **10 min**;
`declutter --llm` up to 50 × 15 s = **12.5 min**. There is no wall-clock cap.

**Fix — one shared budget object, used by every offline LLM loop:**

```python
# NEW src/pmb/core/llm_budget.py
"""Wall-clock + call-count budget for offline LLM passes.

Every batched/offline LLM loop (keyed suggestions, declutter judge,
consolidation clusters) must construct one budget at the top and check
allow() before EVERY call. Per-call timeouts bound a single call; this
bounds the WHOLE pass.
"""
from __future__ import annotations
import time


class LLMBudget:
    def __init__(self, max_calls: int = 40, max_wall_s: float = 120.0):
        self.max_calls = int(max_calls)
        self.max_wall_s = float(max_wall_s)
        self._t0 = time.monotonic()
        self.calls = 0

    def allow(self) -> bool:
        return (self.calls < self.max_calls
                and (time.monotonic() - self._t0) < self.max_wall_s)

    def spend(self) -> None:
        self.calls += 1

    def report(self) -> dict:
        return {"llm_calls": self.calls,
                "elapsed_s": round(time.monotonic() - self._t0, 1),
                "max_calls": self.max_calls, "max_wall_s": self.max_wall_s}
```

Config (additive): `llm.offline_max_calls` (int, 40), `llm.offline_budget_s`
(float, 120.0). Wire into:
- `write.py suggest_keyed_from_llm` — `budget = LLMBudget(cfg…)`; loop:
  `if not budget.allow(): out["stopped"] = "budget"; break`, `budget.spend()`
  after each `llm.complete`; merge `budget.report()` into the result.
- `maintenance/declutter.py _llm_judge` — same pattern (replaces the bare
  `pool[:LLM_CANDIDATE_CAP]` as the only bound; keep the cap too).
- The consolidation cluster loop (find it: `rg -n "def consolidate" src/pmb/`;
  it lives in the engine/health consolidation path) — same pattern, so a slow
  Ollama can never hold `pmb consolidate` for an hour.

**Tests:** mocked LLM with a controllable clock (inject `max_wall_s=0.01`) →
loop stops after first call with `stopped="budget"`; `max_calls=2` → exactly 2
calls; result carries `llm_calls`/`elapsed_s`.

## B3 — hooks become daemon clients with a hard fallback

**File:** `src/pmb/cli/commands/ambient.py:77` (`prepare-context`), plus
`session-restore`.

```python
def _try_daemon(payload: dict, timeout_s: float = 0.5) -> str | None:
    """One cheap HTTP attempt against a live daemon. None on ANY failure —
    the cold path below is the contract, the daemon is an accelerator."""
    try:
        from pmb.mcp.registry import find_live_daemon  # add: kind=="daemon"
        info = find_live_daemon()
        if not info:
            return None
        import json as _json
        import urllib.request
        tok = (Path(info["pmb_home"]) / "daemon.token").read_text().strip()
        req = urllib.request.Request(
            f"http://127.0.0.1:{info['port']}/internal/hook/prepare-context",
            data=_json.dumps(payload).encode("utf-8"),
            headers={"Authorization": f"Bearer {tok}",
                     "Content-Type": "application/json"},
        )
        with urllib.request.urlopen(req, timeout=timeout_s) as r:
            if getattr(r, "status", 200) != 200:
                return None
            body = _json.loads(r.read().decode("utf-8"))
            # version handshake
            if body.get("version") != pmb.__version__:
                return None
            return body.get("context") or ""
    except Exception:
        return None
```

`prepare-context` flow: read stdin → `_try_daemon(...)`; on `None` → the
existing in-process cold path **unchanged**. Total added latency when the
daemon is down: one failed localhost connect, < 50 ms.

**Autostart:** config `daemon.autostart` (bool, default **True** — this is the
whole point of the feature; users who object set it false). When the cold path
runs AND autostart is on AND no live daemon AND no recent attempt
(`$PMB_HOME/daemon.autostart_stamp` mtime > 10 min ago): touch the stamp and
spawn `pmb daemon start` detached. The CURRENT hook call still answers cold;
the NEXT message hits the warm daemon. `pmb connect`/`pmb hooks install` print
a line explaining this ("a background memory daemon (~400 MB RSS) will start on
first use; disable with `pmb config set daemon.autostart false`").

**Tests:** unit-test `_try_daemon` against a stub `http.server` (token ok /
wrong token / wrong version / timeout / connection refused → all degrade to
None); e2e-lite: spawn `pmb daemon run` in a subprocess on a temp PMB_HOME with
a tiny workspace, call `pmb prepare-context --stdin` and assert the output came

## B4 — durable write outbox (replace fire-and-forget daemon threads)

**File:** `src/pmb/core/engine/batch.py:58-121`.

**Verified data-loss window:** `record_batch_async` returns `{"ok": true}` and
runs the ENTIRE `record_batch` (SQLite insert included) in a `daemon=True`
thread (batch.py:87-105). Process exit before the thread finishes → **items
silently lost**. The durable `PersistentEmbedQueue` (core/embed_queue.py) only
covers embeddings *after* the event row exists.

**Fix — synchronous outbox enqueue, asynchronous drain** (mirror the
PersistentEmbedQueue pattern):

```sql
-- new table in events.sqlite (add to the DDL in core/events.py / sqlite_helper)
CREATE TABLE IF NOT EXISTS write_outbox (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    workspace_id TEXT NOT NULL,
    created_at  REAL NOT NULL,
    items_json  TEXT NOT NULL,
    status      TEXT NOT NULL DEFAULT 'pending',  -- pending|done|failed
    attempts    INTEGER NOT NULL DEFAULT 0,
    last_error  TEXT
);
CREATE INDEX IF NOT EXISTS idx_outbox_status ON write_outbox(status, id);
```

`record_batch_async` becomes: validate lightly → `INSERT INTO write_outbox`
(one synchronous write, ~1 ms — the durability point) → ensure the drainer
thread is running → return `{"ok": True, "n": n, "outbox_id": id}`.

Drainer (one per Engine, daemon thread, same lifecycle as the embed worker):
loop `SELECT … WHERE status='pending' ORDER BY id LIMIT 1` →
`self.record_batch(items)` → `status='done'`; on exception `attempts += 1`,
exponential backoff (1.5 s base), `status='failed'` + error_log (B5) after 5
attempts. `recover_on_start()`: Engine init schedules a drain of leftover
pendings (this is what makes a crash lose NOTHING). Prune `done` rows older
than 7 days during maintenance.

`wait_for_writes()` (batch.py:123) must now also wait for the outbox to be
empty for this workspace — tests and `pmb mcp serve` shutdown rely on it.

Config: `write.outbox` (bool, default **True** — strictly safer; `false`
restores the old thread path for bisecting).

**Tests:** enqueue 3 batches, kill the drainer before it runs (don't start it),
re-init Engine → all 3 land; failing `record_batch` (monkeypatch raise) → row
goes `failed` after 5 attempts with `last_error` set, others still processed;
`wait_for_writes` returns only when outbox drained; default-on suite stays green.

# PHASE E — memory quality (write less junk, keep state honest)

## E1 (P1) — negation must CLOSE the keyed value, not only vice-versa

Today: positive value archives older negations (Task 5). The REVERSE case is
unhandled: `user::city = Tampa` exists, then the user says
`"I no longer live in Tampa"`. `_NEGATION_RE` blocks promotion
(attributes.py:174-179), the negation is stored as a plain fact — and
**`user::city = Tampa` stays the asserted current value forever.**

Write-time hook (same place as `_maybe_promote_current_state` /
`_archive_obsolete_negations` — `rg -n "_maybe_promote_current_state" src/pmb/core/engine/write.py`):
when a NEW fact has `detect_negated_state(content) == attr` (post-A1 detector,
so user-subject only) and a CURRENT keyed `user::<attr>` exists with
`timestamp < new fact's`:
- stamp the keyed fact's metadata: `valid_to = <new fact ts>`,
  `closed_by = <new ulid>`, `closed_reason = "negated_by_user"`;
- do NOT archive it (it stays correct history for `keyed_fact_as_of`,
  write.py:547);
- ensure the current-value readers skip closed values: find them via
  `rg -n "keyed_fact_key|current.*keyed|valid_to" src/pmb/core/engine/` and add
  a `valid_to is None` filter wherever "current value" is resolved (recall
  surfacing, repair pass `attrs_with_value`, prepare context).

Config: `keyed.close_on_negation` (bool, default True). **Tests:** Tampa case —
after the negation, "where do I live" recall does NOT assert Tampa as current;
`keyed_fact_as_of(<before negation>)` still returns Tampa; repair pass does not
resurrect it.

## E3 (P2) — "what NOT to record" in the agent-facing docs

Add a compact DON'T-record list to the `record_batch`/`record_fact` docstrings
(post-D1 they're short — add one line + put the full list in the server
instructions block) and to the `pmb connect` template:
- no secrets/tokens/keys (they'll be redacted — see E5);
- no transient tool output, stack traces, or file listings as "facts";
- no restating repo content (code structure, git history) — memory is for
  what's NOT derivable from the repo;
- future intent → `goal`, not fact (rule already exists — keep it).

## E4 (P2) — importance discipline at write time

Agents habitually pass `importance=0.9` for routine activities, polluting
ranking. In the shared write path: for `event_type="activity"` without
`pin=true`, clamp importance to `min(importance, write.max_activity_importance)`
(config, float, default **0.8**); stamp `metadata.importance_clamped = original`
when clamped. Facts/lessons/goals untouched. **Tests:** activity 0.95 → stored
0.8 with breadcrumb; pinned activity 0.95 → kept; fact 0.95 → kept.

## E5 (P2) — secret redaction on the write path (verify, then wire)

`src/pmb/security/redact.py` exists. Verify whether `record_fact`/
`record_batch` apply it (`rg -n "redact" src/pmb/core/engine/ src/pmb/mcp/`).
If not wired: apply to fact/lesson/activity content before insert behind
`write.redact_secrets` (bool, default True) — replace matches with
`[redacted:<kind>]`, stamp `metadata.redactions = n`, and log to errlog
component `redact` (so it's visible in doctor, not silent). Never store the
original. **Tests:** an AWS-style key and a bearer token in content are masked;
normal content untouched; flag off restores old behavior.

## E6 (P3) — near-duplicate suppression at write time

`core/engine/dedup.py` exists — verify which paths use it (`rg -n "dedup" src/pmb/core/engine/`).
Requirement: an EXACT-normalized duplicate of an ACTIVE fact written within
24 h must not create a second row — bump `access_count`/`last_seen` on the
existing row instead and return the existing ulid with
`{"deduped": true}`. If dedup.py already does this for `record_batch`, extend
to `record_fact`; add the config `write.dedup_window_h` (float, default 24, `0`
= off). **Tests:** same fact twice within window → one row; different
workspaces → two rows; window 0 → two rows.
